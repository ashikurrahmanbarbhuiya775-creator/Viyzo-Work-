# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public issues, discussions, screenshots, or social posts. Do not include real user data, access tokens, payment secrets, passwords, OTPs, or private keys.

Use GitHub's **Report a vulnerability / private security advisory** feature for this repository if it is available. If private reporting is not available, contact the project maintainer privately before sharing technical details publicly.

When reporting, include:
- A concise description of the issue and affected component.
- Reproducible steps using only accounts and data you control.
- Potential impact and any suggested mitigation.
- App version, commit, or workflow run where relevant.

## Scope and safe testing

- Do not access another person's account or data.
- Do not test with real payment credentials or real money.
- Do not perform denial-of-service, destructive testing, or social engineering.
- Stop testing if you encounter private information.

## Response expectations

The project maintainer will review reports as capacity allows, confirm receipt when possible, assess severity, and coordinate a fix and disclosure. No response-time guarantee is currently offered.

## Credential handling

Never commit secrets to this repository or place server credentials in the Android app. If a credential is exposed, revoke/rotate it immediately and review access logs.
